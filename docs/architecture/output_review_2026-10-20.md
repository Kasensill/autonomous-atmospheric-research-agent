# 2026-10-20：外部输出评价的核查与改进

## 分批实施

HITL 已作为独立功能提交 `ea09ded`；本文件追踪随后两批输出质量改进。
所有结论区分代码行为测试、真实 API 测试和未验证的科学判断。

## 第一批设计：已定位的缺陷

1. 天气工具结构化结果已有云量与风向，证据文本却遗漏；补齐 evidence_text，继续明确是模型当前条件。
2. 正式定稿按正文实际引用 ID 筛选来源，不重新编号；同页两片段被分别引用时保留两个编号。
3. Trace 记录工具名、允许的 query/location/url 参数（截断，URL 去查询串），结果条数、接纳数、重复数；记录条件路由与预算拦截原因。
4. 简要请求约束为正文最多 900 字符、三条解释和三条局限；模型按要求写作，程序检查长度并强制修订。
5. 长期记忆暂只接受完整、已核验、非当前天气报告；旧天气快照按问题与 Open-Meteo 来源过滤，不删除历史文件。
6. 记忆召回去除部分通用词，要求至少三个词项重合且覆盖查询词项 15%；这是保守工程初值，不宣称已校准最优。
7. 核验增加模型产品/站点实测区分、前后矛盾与归因约束；题集从五条扩大为八条，含两个正例、六个负例。
8. 去重已存在；补齐同一工具返回列表内的完全重复去重。语义近似不同于相同 ID，不能据此宣称语义去重已完成。

## 第二批：先研究再修改

### 检索准入与噪声评测

参考 [阿里云知识库文档](https://www.alibabacloud.com/help/en/model-studio/rag-knowledge-base)：提高门槛可能减少噪声也会漏掉相关资料，需要命中测试调节。
使用 `evals/relevance_gate_cases.json`，按 query 分校准四题、留出四题，总计六条正例、十六条显式负例。
读取实际知识库章节、调用当前 qwen3.7-text-rerank，保存全部分数。

- 只用校准集选出暂定门槛 **0.07**，优先不误拒正例，再减少误收。
- 校准集：正例 3 条均保留，负例误收从 8 降到 0。
- 留出集：正例 3 条均保留，负例误收从 8 降到 **3**；接纳结果中的已标噪声比例从 72.7% 降到 **50%**。
- 这组样本是刻意构建的 query-passage 对，不是完整检索候选分布，也没有独立标注者；仍有明显误收，不宣称消除噪声。
- 原有十二题用同一真实候选做门槛前后对照：Hit=1.000、MRR=0.9583、Coverage=0.8889，前后相同，十二题均成功，无 API 错误。
- 生产工具在 Rerank 成功时执行门槛，允许零结果；降级到向量/BM25/RRF 时不滥用同一分数阈值，明确 `applied=false` 与警告。
- 检索评测增加显式负来源、已标噪声比例、标注覆盖率；未标注不等于无关。当前只有少量负标签，不能把低噪声值当全面精度。
- 顺便修正一个指标边界：无来源的候选占据原排名，不应删除后把第二名误算第一名。

### 恢复与时效

参考 [Open-Meteo 文档](https://open-meteo.com/en/docs)：当前条件是天气模型产品，需保留时次与时区。
新增 `valid_at` 和 `fetched_at`；天气 `valid_at` 由接口时次与地点时区组成，不用抓取时间冒充数据时间。
当前条件采用可配置的两小时新鲜度窗口，时间未知或明显未来时间也要求重新查询；这是业务默认值，不是官方有效期。
原证据保留，`usable_evidence` 过滤过期天气，评估/引用/报告只读取适用视图；E 编号保留原位置，不压缩重编号。
旧天气 ToolMessage 的模型输入视图替换为“过期，请重新查询”，保留协议 ID，不改写原始消息。
恢复记录展示过期条数；普通机制资料不因等待过期。用户改变地点/年份后的语义适用性重评估仍未实现。

### 补查与受限原因

Agent 输入明确包含已有适用证据、上轮 assessment 和剩余预算；提示定向补缺口，不无理由重复同义检索。
这不等同于语义去重或强制工具缓存，后两者未实现。
程序记录 `program_limitations`（轮次耗尽、本批请求超额度等），模型单独返回 `limitation_reasons`
（能力缺口、冲突、资料不足）；两类在报告输入与 debug 分开显示，允许多个原因并存。

## 不直接照搬的建议

- 单地点海平面气压及一天趋势不能独立证明区域高压控制；先不为消除局限文字而增加天气归因能力。
- 气候态分析需要明确基准期、时间窗口、变量与产品口径，不通过简单取一两年同期值冒充常年平均。
- jieba 已通过 lru_cache 进程内缓存；Serverless 预热是部署场景优化，当前不增加启动复杂性。
- 工具上限是八次、研究上限三轮；“五次即达工具上限”的外部推测已纠正。
- 核验已有负例评测，本轮扩充而不是从零新增。
- 不把单次 pass 或一小组评测解释成科学正确性保证。

# 2026-10-20：外部输出评价的核查与改进

## 分批实施

所有结论区分代码行为测试、真实 API 测试和未验证的科学判断。

## 第一批设计：已定位的缺陷

1. 天气工具结构化结果已有云量与风向，证据文本却遗漏；补齐 evidence_text，继续明确是模型当前条件。
2. 正式定稿按正文实际引用 ID 筛选来源，不重新编号；同页两片段被分别引用时保留两个编号。
3. Trace 记录工具名、允许的 query/location 参数（截断），结果条数、接纳数、重复数；记录条件路由与预算拦截原因。
4. 简要请求约束为正文最多 900 字符、三条解释和三条局限；模型按要求写作，程序检查长度并强制修订。
5. 长期记忆暂只接受完整、已核验、非当前天气报告；旧天气快照按问题与 Open-Meteo 来源过滤，不删除历史文件。
6. 记忆召回去除部分通用词，要求至少三个词项重合且覆盖查询词项 15%；这是保守工程初值，不宣称已校准最优。
7. 核验增加模型产品/站点实测区分、前后矛盾与归因约束；题集从五条扩大为八条，含两个正例、六个负例。
8. 去重已存在；补齐同一工具返回列表内的完全重复去重。语义近似不同于相同 ID，不能据此宣称语义去重已完成。

## 第二批待研究事项

- 检索准入：先取得正负相关样本与真实 rerank 分数，校准阈值后决定是否启用；降级路径无同尺度分数，不能套用相同阈值。
- 评测噪声：增加“明确标注无关”的片段比例；未标注片段不是自动无关，避免误导 Precision。
- 过度检索：把已获得证据与缺口明确交回模型，结合 Trace 判断；不能从三轮次数直接断言恢复丢上下文。
- 恢复时效：按数据本身时间与类型检查，而不是固定按暂停时长；通用机制不因等待过期。
- 受限原因：区分预算、能力缺口、证据冲突、资料不足，可并存；机械原因与模型判断分开。

## 不直接照搬的建议

- 单地点海平面气压及一天趋势不能独立证明区域高压控制；先不为消除局限文字而增加天气归因能力。
- 气候态分析需要明确基准期、时间窗口、变量与产品口径，不通过简单取一两年同期值冒充常年平均。
- jieba 已通过 lru_cache 进程内缓存；Serverless 预热是部署场景优化，当前不增加启动复杂性。
- 工具上限是八次、研究上限三轮；“五次即达工具上限”的外部推测已纠正。
- 核验已有负例评测，本轮扩充而不是从零新增。
- 不把单次 pass 或一小组评测解释成科学正确性保证。
